4層構成のシングルページアプリケーションです。データベースは使用しておらず、JSON ファイルを起動時にメモリへ読み込む方式で動作しています。

構成上の重要な性質

データは読み取り専用として扱われています。 mock_data.py が起動時に JSON を読み込み、以降はモジュールレベルの Python リストとしてメモリに保持されます。書き込み系のエンドポイントは実装されていないため、アプリケーションから加えた変更は一切永続化されません。サーバーを再起動すると JSON ファイルの内容に戻ります。

リモート環境での構成（2026年8月時点の変更）

参加者がリモート VM 上で稼働させ手元のブラウザから接続する構成に対応するため、client/vite.config.js に host: true と /api → localhost:8001 のプロキシを設定しています。この結果、外部に公開が必要なポートは 3000 のみです。8001 は Vite 経由となるため公開不要です。あわせて api.js および Reports.vue の絶対 URL を相対パスへ変更しました。

フィルター処理の実装

main.py に2つの共通関数があり、エンドポイント間で再利用されています。

  • apply_filters(items, warehouse, category, status) — 値が 'all' または未指定のフィルターはスキップします。category と status は小文字化して比較するため大文字小文字を区別しません。一方 warehouse は完全一致で比較しており、扱いが統一されていません。
  • filter_by_month(items, month) — order_date に対する部分一致で判定します。QUARTER_MAP により Q1-2025 形式の四半期指定にも対応しますが、2025年のみがハードコードされています。 2026年以降のデータでは四半期フィルターが機能しません。

06データフロー

オペレーターがフィルターを操作してから画面が更新されるまでの経路です。

  1. 操作。 オペレーターが FilterBar.vue のセレクトを変更します。
  2. 共有状態の更新。 composables/useFilters.js のモジュールレベル ref（selectedPeriod / selectedLocation / selectedCategory / selectedStatus）が書き換わります。これはシングルトンであり、全ビューが同一のインスタンスを共有します。
  3. 変更の検知。 各ビューが watch でフィルターを監視しており、変化を検知して再読み込み関数を呼びます。
  4. クエリの組み立て。 getCurrentFilters() が UI の状態を API の語彙へ変換します（selectedLocation → warehouse、selectedPeriod → month）。
  5. HTTP リクエスト。 api.js が URLSearchParams でクエリ文字列を構築し、'all' の項目は送信しません。Vite が /api を 8001 へ転送します。
  6. サーバー側フィルタ。 FastAPI が apply_filters と filter_by_month をメモリ上のリストへ適用します。
  7. 検証と応答。 response_model が指定されたエンドポイントでは Pydantic がスキーマを検証してから JSON を返します。
  8. 状態への格納。 ビューは生データを ref に格納します。
  9. 派生値の算出。 集計・整形・チャート用データは computed で算出されます。依存が変わるまでキャッシュされます。
  10. 描画。 テンプレートが更新されます。チャートは外部ライブラリを使わず、自作の SVG（viewBox によるスケーリング）です。
設計として評価できる点

「生データは ref、派生データは computed」という原則が、Reports.vue を除く全ビューで一貫して守られています。フィルター状態を composable のシングルトンで共有する設計も適切で、ビュー間を移動してもフィルターが保持されます。この土台は作り直す必要がありません。

08横断的関心事（composables）

useFilters.js — 共有フィルター状態

モジュールレベルの ref によるシングルトンです。4種のフィルター（期間・拠点・カテゴリー・ステータス）を保持し、getCurrentFilters() が UI の語彙を API の語彙へ変換します。Reports.vue を除く全ビューが利用しています。

useI18n.js — 翻訳と通貨

自作の i18n 実装です。外部ライブラリ（vue-i18n 等）は使用していません。

  • ロケールは localStorage（キー app-locale）に永続化され、既定値は 'ja' です（useI18n.js:11）。つまりアプリは日本語で起動します。
  • t(key) はドット記法でネストしたキーを解決します。見つからない場合は英語へフォールバックし、それでも無い場合はキー文字列そのものを返します。画面に reports.title のような文字列が表示されていれば、翻訳定義の欠落です。
  • 固有名詞用の専用関数を持ちます（translateProductName / translateCustomerName / translateWarehouse）。倉庫名は都市名マッピングと Warehouse X-## パターンの2系統で処理されます。
  • 翻訳定義は locales/en.js（328 行）と locales/ja.js（382 行）です。
通貨がロケールに連動している点について

useI18n.js:15-17 で、表示通貨がロケールから自動決定されています（ja → JPY、en → USD）。そして utils/currency.js:3 に為替レートが定数として直書きされています。

const USD_TO_JPY = 150

結果として、言語を日本語に切り替えると全画面の金額が固定レート 150 で換算表示されます。 既定ロケールが 'ja' であるため、東京拠点のオペレーターが通常目にする金額はすべてこの換算値です。レート更新の手段はコード変更以外にありません。業務上の影響について、Meridian のご判断を仰ぐべき事項と考えます。

useAuth.js — 認証（モック実装）

認証は実装されていません。isAuthenticated は ref(true) の固定値で、logout() は console.log と alert() のみです。ユーザー情報はハードコードされ、ロケールに応じて日本語名（田中 太郎）と英語名（John Doe）を切り替えます。

別案件の痕跡

useAuth.js:6 のユーザーのメールアドレスが john.doe@catalystcomponents.com となっています。Meridian Components ではありません。 前任ベンダーが他クライアント向けの成果物を流用した際の残存と考えられます。動作への影響はありませんが、画面上に表示される情報であり、修正すべき箇所です。
