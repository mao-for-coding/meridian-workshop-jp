RFP には「少なくとも8件の問題」と記載されていました。調査の結果、これらは8つの独立した不具合ではありませんでした。

原因の連鎖を特定しました

D-04 → D-03。 api.js にレポート系のラッパー関数が無かったため、Reports.vue は axios を直接呼ぶしかありませんでした。そこから共通基盤への未接続が連鎖しています。

したがって修正は「症状を1つずつ潰す」のではなく、まず api.js を直し、そのうえでビューを既存パターンへ移行する順序で実施しました。提案書の技術アプローチに記した「原因が共通であれば複数の症状が単一の修正で解消する」が、そのまま当てはまりました。

実装中に解消した不整合

予算上限の入力欄が USD 固定である一方、結果表示は日本語ロケールで JPY となる状態でした。アプリ全体が表示言語に応じて通貨を切り替えているため、この欄のみ固定なのは不整合です。入力欄を表示通貨に追随させ、API へは USD の基準値に戻して送信する形に改めました。

未修正の欠陥をテストとして記録しています

ご判断待ちや範囲外の欠陥は test.fail() で「失敗するのが正しい」と宣言しています。Playwright はこれを想定どおりの失敗として合格に数えるため、スイート全体は緑（終了コード 0）を保ちます。

そして欠陥を修正するとテストが成功に転じ、スイートが赤になります。これは異常ではなく修正完了の合図です。該当宣言を外せば、以降は通常の回帰テストとして機能します。修正すべき事項の一覧が実行可能な形で残り、完了が自動検知される仕組みです。

R1 の完了時には、この仕組みにより 7 件が成功に転じました。現在残っているのは 4 件です（D-01・D-02・D-06・D-08）。

訂正 — 既存テストの件数と成否

提案時、同梱の tests/TEST_SUMMARY.md の記述にもとづき「バックエンド API テスト 55 件が全件パス」とご報告しました。フェーズ1の実測では 40 件収集・38 件パス・2 件失敗であり、この記述は事実と異なります。

失敗している 2 件は需要予測データに期待される SKU（SNR-420）が存在しないことによるもので、当社の着手前から失敗していた既存の不整合です（変更前のコードで再現確認済み）。R2 で 35 件を追加した現在は 75 件収集・73 件パス・2 件失敗です。

バックエンド層に相応のカバレッジが存在するという結論、および R3 のスコープ判断・見積もりへの影響はありません。テストが常時 2 件赤である状態は IT 部門の承認判断を妨げるため、早期の解消をお勧めします（§06）。

06ご判断をお願いしたい事項

技術的には対応可能ですが、当社の判断で決めるべきでない事項です。フェーズ4の着手前にご回答をいただけますと、計画に反映できます。

  1. D-05 — 為替レートの扱い。 utils/currency.js に USD_TO_JPY = 150 が定数として直書きされています。既定ロケールが日本語であるため、東京拠点のオペレーターが通常目にする金額はすべてこの固定レートによる換算値です。レート更新の手段はコード変更以外にありません。
    選択肢: (1) 固定レートを維持、(2) 設定可能にする、(3) 日本語表示でも USD を維持。会計上の扱いに関わるため当社では判断できません。
  2. D-02 — 発注実行機能の去就。 Dashboard.vue が <PurchaseOrderModal> を参照していますが、コンポーネントが存在しません。「Create PO」ボタンは表示されるものの押しても何も起きません。これは発注の実行を担う UI であり、前提条件 A5（発注実行の連携は範囲外）により R2 の納品範囲外です。当社の判断で UI を削除することは避け、現状のまま残しています。
    選択肢: (1) 発注実行機能として完成させる（別途お見積もり）、(2) 動作しない UI を撤去する、(3) 現状維持。(1) または (2) を推奨します。
  3. D-01 — タスク機能の去就。 TasksModal.vue（621行）が未実装の /api/tasks に依存しており、全ページの起動時に 404 エラーが発生します（App.vue から呼ばれるため）。コンソールにエラーが出続ける状態は IT 部門の異常検知を妨げます。
    選択肢: (1) バックエンドを実装して完成させる（別途お見積もり）、(2) UI ごと撤去する。本提案の範囲外です。
  4. D-06 — Backlog.vue の去就。 152行のビューが存在しますが、ルートが未定義で画面から到達できません。バックログ表示は Dashboard.vue にインライン実装があるため、機能面の欠落は生じていません。
    選択肢: (1) ルートを追加して復活、(2) 削除。
  5. D-08 — 支出画面のフィルター。 /api/spending/* がクエリパラメータを受け取らないため、UI 上でフィルターを操作しても支出データに反映されません。 フィルターバーが表示されているため、オペレーターは効くと考えている可能性があります。対応可否のご判断をお願いします。
  6. 需要予測テストの失敗 2 件。 demand_forecasts.json に SNR-420 を追加するか、テストを現行データに合わせるかの判断が必要です。データの正誤はコードからは判断できません。
